Your request:

    %1$s

Expected request scheme:

    %2$s move PATH RULE [OPTIONS]
    %2$s move [PATH/]DEEP RULE [OPTIONS]
    %2$s move [PATH/][DEEP/]PATTERN RULE [OPTIONS]

    ... to relocate regular files that meet certain criteria located in a given
        processing directory.

        Empty subdirectories will finally be removed (see CLEAN).

Parameters:

    PATH      - A path to be examined.
              - Default: the path of the current working directory (cwd)
    DEEP      - One of {**, .**, :**}
                **      : also list files contained in visible* subdirectories
                .**     : [not yet implemented:]
                          also list files contained in invisible* subdirectories
                :**     : also list files contained in any subdirectory
              - Default : don't list files contained in any subdirectory
    PATTERN   - A pattern for matching the simple filenames of the files to be listed.
                May contain usual wildcards {?, *} with their usual meanings.
                May be prefixed by {:} -> also list invisible* files that matches
                the rest of the PATTERN. By default only list visible* files,
                unless the pattern starts with dot (.) and thus explicitly matches
                invisible* files.
              - Default : * (match any visible* file)
    RULE     - A processing rule that has a similar structure to a relative path,
               but which can contain TOKENs that are interpreted during
               processing. A resulting relative path will be resolved from the
               processing directory!

               Tokens (case sensitive!):

               @Y -> the year the file in question was last modified.
               @M -> the month the file in question was last modified.
               @D -> the day the file in question was last modified.
               @h -> the hour the file in question was last modified.
               @m -> the minute the file in question was last modified.
               @s -> the second the file in question was last modified.
               @X -> the current filename extension of the file in question.
               @N -> the current filename without extension of the file in question.
               @F -> the current filename with extension of the file in question.
               @P -> the actual filename of the processing directory.
               @p -> the filename of the current parent directory of the file
                     in question.
               @R -> the relative path from the processing directory to the
                     file in question.
               @# -> a hex encoded SHA1 hash value over the content of the file
                     in question. If the actual file name already contains such a
                     hash value, that value is used instead of recalculating it.
               @! -> a hex encoded time stamp of the last modification of the file
                     in question, accurate to a second. If the actual file name
                     already contains such a timestamp, that value is used instead
                     of recalculating it.
               @@ -> The `at` symbol
    OPTIONS   - Consists of [n:N_PATTERN] [x:X_PATTERN]
    N_PATTERN - An extended pattern for (additionally) matching the simple
                filenames of the files to be listed.
                Consists of [METHOD:[OPTION:]]VALUE
                METHOD - One of {rx, wc} (case-insensitive)
                         rx : the VALUE is treated as a regular expression.
                         wc : the VALUE is treated as the full file name,
                              but allows the use of usual wildcards {?, *}.
                       - Default: wc (pattern with wildcards)
                OPTION - One of {cs, ci} (case-insensitive)
                         cs : the pattern will be applied case-sensitive.
                         ci : the pattern will be applied case-insensitive.
                       - Default: ci (case-insensitive)
                VALUE  - A pattern value to be applied to the METHOD along
                         with the simple filenames in question.
    X_PATTERN - An extended pattern for matching the simple filenames
                of files to be excluded from listing.
                Consists of [METHOD:[OPTION:]]VALUE  ... (see N_PATTERN)
